## 1. Назначение

**Apollo Game Scanner** — портативная утилита для Windows, которая:

- сканирует папку с играми (каждая подпапка первого уровня считается игрой);
- находит в каждой игре `.exe`, отбрасывает установщики, редисты, краш-хендлеры и
  служебные файлы;
- предлагает наиболее вероятный исполняемый файл, но позволяет выбрать другой;
- формирует или дополняет конфигурацию Apollo (`apps.json`, он же формат
  Sunshine) **не перезаписывая уже существующие записи**;
- помечает игры, которые уже есть в конфиге, и даёт их редактировать;
- помогает подобрать обложку: ищет картинку в папке игры, извлекает иконку `.exe`,
  ищет в GameDB (IGDB), SteamGridDB или DuckDuckGo, позволяет выбрать файл вручную;
- конвертирует обложки в PNG без изменения разрешения и складывает их в `covers`;
- сохраняет `apps.json` с резервной копией `.bak` и атомарной заменой файла.

Ключевая идея: **сканер ничего не ломает**. Существующие записи Apollo
сохраняются, неизвестные поля JSON проходят через программу без потерь,
добавляются только новые записи, а любую запись можно открыть и отредактировать
вручную, вплоть до полного JSON.

## 2. Что уже реализовано

### Сканирование

- Папка игр выбирается вручную; каждая подпапка первого уровня — игра.
- Рекурсивный поиск `.exe` на произвольную глубину (с ограничением `MaxDepth`).
- Настраиваемые шаблоны исключения файлов и папок (`*`, `?`, без учёта регистра).
- Пропуск reparse points (символических ссылок и junction) во вложенных папках.
- Подсчёт исключённых файлов и отображение его в строке игры.
- Эвристическая оценка кандидатов: совпадение имени, размер, глубина,
  типовые каталоги (`bin`, `x64`, `game`), штрафы за `launcher`, `config`,
  `crash`, `server`, `x86` и т.п.
- Очистка названия игры от `_`, версий, `repack`, `update`, `hotfix` и т.п.
- Формирование `working-dir` по настройке: папка игры, папка выбранного `.exe`
  или пусто. По умолчанию — папка `.exe`.
- Фоновое сканирование с прогрессом по папкам и отменой через `CancellationToken`
  (программно; отдельной кнопки отмены в UI нет — см. раздел 17).

### Работа с конфигом

- Загрузка/создание/сохранение `apps.json`, «Сохранить как…».
- Сохранение `version: 2`, `env`, `apps` и всех неизвестных полей.
- Построчный разбор записей Apollo со всеми известными полями.
- Терпимое чтение значений: строки/числа/массивы вместо `bool`, числа строками.
- Пометка игр, уже присутствующих в конфиге, по трём правилам (exe внутри папки,
  рабочая папка, нормализованное название).
- Добавление только отмеченных новых игр; существующие повторно не добавляются.
- Ручное добавление записи.
- Пакетные действия для отмеченных (или всех новых) игр и для отмеченных
  записей конфига: поиск обложек и редактирование общих полей.
- Редактирование, удаление и перемещение записей (вверх/вниз).
- Редактор с двумя вкладками: «Основные» и «JSON» (полный доступ ко всем полям).
- Проверка названия и предупреждение, если exe не существует.
- Защита от потери изменений: подтверждение при закрытии, смене конфига,
  создании нового конфига.
- Резервная копия `.bak`, временный файл `.tmp`, атомарная замена через
  `File.Replace` с запасным вариантом.

### Обложки

- Поиск локальной картинки в папке игры и типовых подпапках
  (`artwork`, `cover`, `covers`, `box`, `art`, `media`, `images`, `screenshots`).
- Оценка локальных картинок по имени, ориентации, размеру, расположению.
- Извлечение иконки `.exe` в PNG 128×128.
- GameDB (IGDB) — открытый каталог LizardByte, тот же источник, что использует
  Apollo. Ключ не нужен.
- SteamGridDB через официальный API (нужен ключ).
- DuckDuckGo Images как неофициальный запасной источник (без ключа).
- Окно выбора обложки с превью, размерами и источниками.
- Конвертация PNG/JPG/JPEG/BMP/GIF → PNG без изменения разрешения.
- Имя файла обложки — транслитерированный slug, ограничение 60 символов.
- Кэш скачанных картинок и кнопка его очистки.

### Интерфейс

- Русский интерфейс, два рабочих экрана: «Найденные игры» и «Текущий конфиг».
- Без таблиц/гридов: собственные строки-контролы с чекбоксом, ComboBox и превью.
- Фильтр по названию, режим «Только новые».
- Строка состояния с количеством новых, существующих и игр без exe.
- Меню «Файл», «Настройки», «Справка», горячие клавиши.
- Ручное масштабирование под высокий DPI (проверено на 3840×2160, 200 %).

## 3. Требования и сборка

### Требования

- Windows 10/11 (x64).
- .NET SDK 8.0 для сборки.
- .NET Desktop Runtime 8.0 для запуска (если публикация не self-contained).
- Доступ в интернет — только для онлайн-обложек (необязательно).
- Права на запись рядом с `.exe` — для `settings.json`, `covers`, `cache`.

NuGet-зависимостей нет: используются только WinForms, `System.Text.Json`,
`System.Drawing` и стандартная библиотека.

### Сборка

```powershell
cd D:\Projects\CS\apollo-game-scaner
dotnet build -v q
```

Результат:

```
src\ApolloGameScanner\bin\Debug\net8.0-windows\ApolloGameScanner.exe
```

### Запуск из исходников

```powershell
dotnet run --project src\ApolloGameScanner\ApolloGameScanner.csproj
```

### Публикация

Framework-dependent (маленький размер, нужен установленный Runtime):

```powershell
dotnet publish src\ApolloGameScanner\ApolloGameScanner.csproj `
  -c Release -r win-x64 --self-contained false `
  -p:PublishSingleFile=true
```

Self-contained (Runtime не нужен):

```powershell
dotnet publish src\ApolloGameScanner\ApolloGameScanner.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true
```

Портативность: программа хранит настройки **рядом с `.exe`**, поэтому папку
публикации можно переносить целиком. При публикации в `Program Files` запись
`settings.json` может быть запрещена — программа покажет предупреждение и
продолжит работу без сохранения настроек (см. раздел 17).

### Сборка релиза скриптом

В корне репозитория лежит `release.cmd` — он собирает single-file публикацию,
кладёт `README.md` рядом с exe, упаковывает всё в ZIP и считает SHA-256.
Артефакты попадают в `dist/` (каталог в `.gitignore`):

```bat
release.cmd                        :: текущая версия из .csproj, self-contained
release.cmd 1.2.0                  :: версия 1.2.0, self-contained
release.cmd v1.2.0 --framework     :: framework-dependent (нужен Runtime 8)
release.cmd 1.2.0 --github         :: + тег и GitHub Release через gh
release.cmd 1.2.0 --github --yes   :: без интерактивного подтверждения
```

Результат:

```
dist\v<версия>\ApolloGameScanner.exe   (+ README.md)
dist\ApolloGameScanner-<версия>-win-x64.zip       (self-contained)
dist\ApolloGameScanner-<версия>-win-x64-fdd.zip   (framework-dependent)
dist\ApolloGameScanner-<версия>-win-x64*.zip.sha256
```

Параметры:

| Флаг | Назначение |
|---|---|
| `--framework` | framework-dependent сборка (нужен .NET Desktop Runtime 8) |
| `--self-contained` | self-contained сборка (по умолчанию) |
| `--github` | создать/обновить тег `v<версия>` и GitHub Release (требуется `gh`) |
| `--yes` | не спрашивать подтверждение |
| `--allow-dirty` | разрешить релиз при незакоммиченных изменениях |
| `-h`, `--help` | справка |

Особенности:

- версия по умолчанию читается из `<Version>` в `ApolloGameScanner.csproj`;
- при `--github` скрипт проверяет чистоту рабочего дерева, создаёт аннотированный
  тег, отправляет его в `origin` и вызывает `gh release create` (или
  `gh release upload --clobber`, если релиз уже существует);
- имена переменных внутри `.cmd` не должны совпадать со свойствами MSBuild
  (`OutDir`, `Version`, `PublishDir` и т.п.) — иначе параметры публикации
  ломаются.

### Настройки проекта

## 4. Быстрый старт

1. Запустите `ApolloGameScanner.exe`.
2. В поле **«Исходный конфиг»** укажите путь к существующему `apps.json`
   (обычно `C:\Program Files\Apollo\config\apps.json` или аналогичный).
   Если конфига нет — нажмите **«Файл → Новый конфиг»**.
3. В поле **«Папка с играми»** выберите каталог, где лежат папки игр.
4. Нажмите **«Сканировать»**.
5. Проверьте найденные игры:
   - белые — новые, их можно отметить галочкой;
   - зелёные — уже есть в конфиге (галочка недоступна);
   - серые — `.exe` не найден или все исключены.
6. При необходимости выберите другой `.exe` в выпадающем списке строки или
   нажмите **«Изменить…»** для настройки параметров и обложки.
7. Для массовой обработки используйте **«Найти обложки…»** и
   **«Изменить отмеченные…»** над списком игр.
8. Нажмите **«Добавить отмеченные (N)»**.
9. Перейдите на вкладку **«Текущий конфиг»**, проверьте записи.
10. Нажмите **«Сохранить»**. Рядом появится `apps.json.bak` с предыдущей версией.
11. Перезапустите Apollo (или перечитайте конфиг), чтобы игры появились в списке.

## 5. Пользовательский сценарий

Подробная последовательность того, что происходит внутри:

1. **Старт.** Читается `settings.json` рядом с `.exe`. Если он есть, подставляются
   последний конфиг, последняя папка игр, шаблоны исключений, папка обложек,
   ключ SteamGridDB, режим «Только новые». Если конфиг существует — он молча
   загружается.
2. **Сканирование.** Перечисляются папки первого уровня. Для каждой:
   обход `.exe`, применение исключений, оценка кандидатов, выбор лучшего,
   формирование черновика записи (`Draft`), поиск локальной обложки для превью.
3. **Сопоставление.** Каждая найденная игра сравнивается с записями конфига.
   Совпавшие помечаются `Existing`, их галочка снимается и блокируется.
4. **Просмотр.** Строки появляются в «Найденных играх». Фильтр и режим
   «Только новые» скрывают ненужное. Смена `.exe` в ComboBox обновляет
   `Draft.Cmd`, сохраняя уже введённые аргументы, и пересчитывает
   `Draft.WorkingDir` по настройке.
5. **Правка.** «Изменить…» открывает редактор. Для новой игры правится черновик,
   для существующей — запись конфига. В редакторе можно задать название,
   exe, аргументы, рабочую папку, обложку, флаги Apollo, `scale-factor`,
   `exit-timeout`, `gamepad` и полный JSON.
6. **Пакетная обработка.** «Найти обложки…» ищет обложку для каждой отмеченной
   игры (или для всех новых, если ничего не отмечено) и сохраняет PNG в
   `covers`. «Изменить отмеченные…» применяет к черновикам только отмеченные
   поля: аргументы, правило рабочей папки (папка игры / папка exe / пусто),
   `scale-factor`, `exit-timeout`, `gamepad`, флаги и действие с обложками
   (поиск, одна картинка для всех, очистка). Те же кнопки есть на вкладке
   «Текущий конфиг» — там они работают с отмеченными записями `apps`.
7. **Добавление.** «Добавить отмеченные» клонирует черновики, назначает `uuid`,
   подставляет название, рабочую папку, команду и иконку exe, добавляет записи
   в конец `apps` и переводит игры в статус `Existing`.
8. **Сохранение.** Конфиг сериализуется, пишется в `.tmp`, старый файл
   сохраняется в `.bak`, `.tmp` атомарно заменяет целевой файл.
9. **Повторное сканирование** после сохранения покажет эти игры как уже
   добавленные. Существующие записи при сканировании не изменяются.

## 6. Архитектура

### 6.1 Слои

Приложение разделено на четыре условных слоя:

| Слой | Что входит | Ответственность |
|---|---|---|
| Модели | `Models/*` | структуры данных, разбор/сериализация JSON |
| Сервисы | `Services/*`, `Services/Covers/*` | файловый ввод-вывод, сканирование, сопоставление, обложки |
| Формы | `Forms/*`, `MainForm.cs` | интерфейс, сценарии, валидация |
| Инфраструктура | `Program.cs`, `DpiScale.cs` | запуск, обработка исключений, масштабирование |

Внешних DI-контейнеров и фреймворков нет: зависимости создаются вручную
(`new SettingsService()`, `new CoverService(settings)` и т.д.).

## 7. Модель данных

### 7.1 `AppEntry`

Одна запись массива `apps`. Поля соответствуют формату Apollo/Sunshine
(`src/process.cpp` в Apollo).

| Свойство | JSON-ключ | Тип | По умолчанию | Назначение |
|---|---|---|---|---|
| `Uuid` | `uuid` | string | `""` | уникальный идентификатор записи |
| `Name` | `name` | string | `""` | отображаемое название |
| `Cmd` | `cmd` | string | `""` | команда запуска (exe + аргументы) |
| `WorkingDir` | `working-dir` | string | `""` | рабочая папка |
| `ImagePath` | `image-path` | string | `""` | путь к обложке (Apollo — только PNG) |
| `Output` | `output` | string | `""` | перенаправление вывода (редко используется) |
| `Detached` | `detached` | string[] | `[]` | список процессов, от которых нужно отвязаться |
| `PrepCmd` | `prep-cmd` | AppCommand[] | `[]` | команды подготовки |
| `StateCmd` | `state-cmd` | AppCommand[] | `[]` | команды состояния |
| `Elevated` | `elevated` | bool | `false` | запуск от администратора |
| `AutoDetach` | `auto-detach` | bool | `true` | автоотвязка дочерних процессов |
| `WaitAll` | `wait-all` | bool | `true` | ждать завершения всех процессов |
| `VirtualDisplay` | `virtual-display` | bool | `false` | виртуальный дисплей |
| `ExitTimeout` | `exit-timeout` | int | `5` | таймаут завершения, сек |
| `ScaleFactor` | `scale-factor` | int | `100` | масштаб интерфейса Apollo, % |
| `UseAppIdentity` | `use-app-identity` | bool | `false` | использовать identity приложения |
| `PerClientAppIdentity` | `per-client-app-identity` | bool | `false` | identity на клиента |
| `AllowClientCommands` | `allow-client-commands` | bool | `true` | разрешить команды клиента |
| `TerminateOnPause` | `terminate-on-pause` | bool | `false` | завершать при паузе |
| `ExcludeGlobalPrepCmd` | `exclude-global-prep-cmd` | bool | `false` | не применять глобальные prep-cmd |
| `ExcludeGlobalStateCmd` | `exclude-global-state-cmd` | bool | `false` | не применять глобальные state-cmd |
| `Gamepad` | `gamepad` | string | `""` | тип геймпада (`auto`, `ds5`, `x360`…) |
| `PresentKeys` | — | `HashSet<string>` | — | ключи, реально присутствовавшие в JSON |
| `Extra` | — | `Dictionary<string, JsonNode?>` | — | неизвестные поля без изменений |

#### `PresentKeys` и `Extra`

- `PresentKeys` нужен, чтобы не раздувать файл: значения по умолчанию не
  записываются, **кроме случаев**, когда ключ уже был в исходном JSON. Тогда
  поле сохраняется даже с пустым/дефолтным значением.
- `Extra` хранит все ключи, которых программа не знает. Они записываются обратно
  без изменений (через `DeepClone`).
- Порядок полей при сериализации фиксированный: сначала известные, затем `Extra`.
- `Clone()` реализован через `FromJson(ToJson())`, то есть копия полностью
  независима, включая `Extra`.
- `CopyFrom` используется редактором при применении JSON.

#### Ограничения обратимости

- Пустые массивы `detached`, `prep-cmd`, `state-cmd` не записываются, даже если
  были в исходном файле (проверяется только `Count > 0`).
- Порядок ключей и форматирование исходного файла не сохраняются: JSON
  переписывается с отступами в 2 пробела.
- Неизвестные поля сохраняются, но их относительный порядок может измениться
  (они добавляются в конец, в порядке словаря).
- `version` всегда записывается как `2` (см. 7.3).

### 7.2 `AppCommand`

| Свойство | JSON-ключ | Тип | По умолчанию |
|---|---|---|---|
| `Do` | `do` | string | `""` |
| `Undo` | `undo` | string | `""` |
| `Elevated` | `elevated` | bool | `false` |
| `Extra` | — | словарь | — |

Неизвестные поля команд тоже сохраняются через `Extra`.

### 7.3 `AppsConfig`

| Свойство | Назначение |
|---|---|
| `Version` | прочитанная версия (по умолчанию 2) |
| `HadVersion` | был ли ключ `version` в файле |
| `Env` | корневой объект `env` (копируется как есть) |
| `Apps` | список `AppEntry` |
| `RootExtra` | неизвестные корневые поля |

Поведение:

- При чтении `version` отсутствует → `Version = 2`, `HadVersion = false`.
- При записи **всегда** пишется `"version": 2`. Фактически это миграция
  конфига версии 1 в версию 2.
- `env` пишется, если был (даже пустой объект).
- `apps` пишется всегда, даже пустым массивом.
- Корневые неизвестные поля (`future-root` и т.п.) сохраняются.
- Пустой файл трактуется как новый конфиг (`AppsConfig()`), а не ошибка.
- Если корень не объект — `InvalidDataException`.
- Если `apps` не массив — записи игнорируются без ошибки.

### 7.4 `DetectedGame`, `ExeCandidate`, `GameStatus`

`ExeCandidate`:

| Поле | Описание |
|---|---|
| `FullPath` | полный путь к `.exe` |
| `RelativePath` | путь относительно папки игры |
| `Size` | размер в байтах |
| `Score` | эвристическая оценка |

`ToString()` выводит `относительный\путь.exe  (12,3 МБ)` или `(512 КБ)`.

`DetectedGame`:

| Поле | Описание |
|---|---|
| `FolderPath` | папка игры |
| `FolderName` | имя папки |
| `Name` | очищенное название |
| `Status` | `New` / `Existing` / `NoExe` |
| `Candidates` | все найденные exe, отсортированные по оценке |
| `SelectedCandidate` | выбранный exe |
| `ExcludedFiles` | сколько файлов отброшено шаблонами |
| `Draft` | черновик `AppEntry` |
| `ExistingApp` | найденная запись конфига |
| `IsSelected` | отмечена ли галочкой |
| `CoverPreviewPath` | путь к превью обложки |

`GameStatus`:

- `New` — есть кандидаты, игры нет в конфиге;
- `Existing` — игра уже есть в конфиге;
- `NoExe` — ни одного подходящего `.exe`.

Игра со статусом `NoExe` всё равно показывается в списке: это сигнал, что папка
похожа на игру, но exe не найден (или исключён шаблонами).

### 7.5 `CoverResult` и `CoverSource`

`CoverResult` — результат онлайн-поиска: `Source`, `Title`, `ThumbUrl`,
`FullUrl`, `Width`, `Height`.

`CoverSource` (`LocalFolder`, `ExeIcon`, `GameDb`, `SteamGridDb`, `DuckDuckGo`,
`Manual`) объявлен, но в текущей версии для UI-логики практически не
используется: источник определяется провайдером/сценарием.

## 8. Форматы файлов

### 8.1 `apps.json`

Пример минимального конфига:

```json
{
  "version": 2,
  "env": {
    "PATH": "C:\\Tools"
  },
  "apps": [
    {
      "uuid": "3f1c0a52-9c1f-4a4e-9d0e-6f6a1c2b7d10",
      "name": "Example Game",
      "cmd": "\"D:\\Games\\Example\\game.exe\"",
      "working-dir": "D:\\Games\\Example",
      "image-path": "C:\\Apollo\\config\\covers\\example-game.png",
      "auto-detach": true,
      "wait-all": true,
      "allow-client-commands": true,
      "exit-timeout": 5,
      "scale-factor": 100,
      "gamepad": "auto"
    }
  ],
  "future-root": {
    "note": "неизвестное поле сохраняется"
  }
}
```

Правила чтения:

| Ситуация | Поведение |
|---|---|
| файл отсутствует | `FileNotFoundException` |
| файл пустой | новый пустой конфиг |
| невалидный JSON | `InvalidDataException` с текстом ошибки |
| корень — массив/строка | `InvalidDataException` |
| `version` — строка/число | приводится к int, иначе 2 |
| `version` отсутствует | 2, `HadVersion=false` |
| `env` не объект | игнорируется |
| `apps` не массив | игнорируется (0 записей) |
| элемент `apps` не объект | пропускается |
| `prep-cmd`/`state-cmd` не массив | игнорируются |
| элемент команды не объект | пропускается |
| `detached` не массив | пустой список |
| `true/false` строками или числами | распознаётся (`true/on/yes/1/enabled`) |
| число строкой | распознаётся |
| массив из одного bool | берётся первый элемент |

Правила записи:

- UTF-8 **без BOM**.
- Отступы 2 пробела, не-ASCII символы не экранируются
  (`UnsafeRelaxedJsonEscaping`) — русские названия читаемы.
- Значения по умолчанию у новых записей опускаются.
- Ранее присутствовавшие ключи сохраняются даже с пустым значением.
- `version` всегда 2.
- `env` и `RootExtra` идут после `apps`.

#### Сохранение и резервные копии

`AppsConfigService.Save`:

1. Вычисляет полный путь, создаёт каталог.
2. Пишет `apps.json.tmp` (UTF-8 без BOM).
3. Если целевой файл существует:
   - пытается `File.Replace(tmp, target, target.bak, ignoreMetadataErrors: true)`;
   - при ошибке — копирует старый файл в `.bak`, удаляет старый, перемещает `.tmp`.
4. Если файла нет — просто перемещает `.tmp` в целевой путь.

Плюсы: запись не оставляет «полуфайл» при нормальном сценарии, предыдущая
версия всегда доступна в `.bak`.

Ограничения: запасной вариант не транзакционен (при сбое между удалением и
перемещением можно остаться без файла, хотя `.bak` останется). `.tmp` при
исключении не удаляется. Сам факт `File.Replace` может не сработать, если файл
удерживается Apollo, — тогда используется копирование/удаление.

### 8.2 `settings.json`

Лежит рядом с `ApolloGameScanner.exe` (`AppContext.BaseDirectory`), а не в
`%APPDATA%`. Это осознанный портативный режим.

```json
{
  "LastConfigPath": "C:\\Apollo\\config\\apps.json",
  "LastGamesFolder": "D:\\Games",
  "ExcludedFilePatterns": [
    "unins*",
    "setup*",
    "*redist*",
    "UnityCrashHandler*"
  ],
  "ExcludedFolderPatterns": [
    "Redist",
    "_CommonRedist",
    "DirectX"
  ],
  "MaxDepth": 0,
  "CoversFolder": null,
  "SteamGridDbKey": "",
  "ShowOnlyNew": false,
  "WorkingDirMode": 1
}
```

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `LastConfigPath` | string? | `null` | последний открытый/сохранённый конфиг |
| `LastGamesFolder` | string? | `null` | последняя папка игр |
| `ExcludedFilePatterns` | string[] | список ниже | шаблоны имён файлов |
| `ExcludedFolderPatterns` | string[] | список ниже | шаблоны имён папок |
| `MaxDepth` | int | `0` | 0 — без ограничения |
| `CoversFolder` | string? | `null` | пусто — `covers` рядом с конфигом |
| `SteamGridDbKey` | string | `""` | API-ключ SteamGridDB |
| `ShowOnlyNew` | bool | `false` | режим «Только новые» |
| `WorkingDirMode` | int | `1` | `0` — папка игры, `1` — папка exe, `2` — пусто |

`WorkingDirMode` определяет, как заполняется `working-dir` у новых записей
(при сканировании, смене exe и добавлении). По умолчанию используется папка
выбранного exe — это исправляет случай, когда игра лежит в корне папки, а exe
находится в `bin\x64`. Уже существующие записи конфига не переписываются.

GameDB собственных настроек не требует: ключ не нужен. Порядок источников
в окне выбора обложки фиксирован: GameDB → SteamGridDB → DuckDuckGo.

Исключения по умолчанию (файлы):

```
unins*, uninstall*, *uninst*, setup*, *setup*, vcredist*, vc_redist*,
vcredist_*, dxsetup*, dxwebsetup*, *redist*, dotnetfx*, ndp*.exe,
UnityCrashHandler*, UnityPlayer*, crash*, *crashhandler*, *report*,
activation*, *activation*, patcher*, *benchmark*, oalinst*
```

Исключения по умолчанию (папки):

```
Redist, _CommonRedist, CommonRedist, DirectX, DotNet, Support, support,
__Installer, installer, Installers
```

Нормализация при загрузке/сохранении (`AppSettings.Normalize`):

- `null`-списки заменяются значениями по умолчанию;
- пустые строки удаляются, значения обрезаются по краям;
- дубликаты удаляются без учёта регистра;
- отрицательный `MaxDepth` становится 0;
- неизвестный `WorkingDirMode` заменяется на `1` (папка exe).

Чтение терпимое: комментарии и висячие запятые допускаются, регистр имён
свойств не важен. При ошибке чтения используются настройки по умолчанию,
а текст ошибки показывается после запуска главного окна.

Сохранение — такое же, как у `apps.json`: `.tmp`, `.bak`, `File.Replace`,
резервный вариант. При невозможности записи показывается предупреждение с
просьбой проверить права на папку программы; программа продолжает работу.

### 8.3 Каталог обложек

Приоритет выбора папки (`CoverService.GetCoversDirectory`):

1. `AppSettings.CoversFolder`, если задан;
2. `covers` рядом с текущим `apps.json`;
3. `covers` рядом с `.exe` (если конфиг ещё не выбран).

Имена файлов: `<slug>.png` для выбранных обложек и `<slug>-icon.png` для иконок
exe. `slug` — до 60 символов, только `a-z`, `0-9`, дефисы; кириллица
транслитерируется; остальные символы заменяются дефисом.

Apollo принимает только PNG — поэтому все обложки конвертируются в PNG.

### 8.4 Кэш

`<папка .exe>\cache\covers\<guid>.<ext>` — временные скачанные изображения.
Расширение берётся из URL, если оно короче 6 символов, иначе `.img`.
Кэш не привязан к игре и не чистится автоматически; в настройках есть кнопка
**«Очистить кэш превью»**.

## 9. Алгоритм сканирования

### 9.1 Этапы

`GameScanner.Scan(root, progress, token)`:

1. Проверяет существование корневой папки.
2. Перечисляет **только первый уровень** подпапок, сортирует по имени
   (`CurrentCultureIgnoreCase`).
3. Для каждой папки сообщает прогресс `(текущий, всего, имя)`.
4. Если имя папки подходит под шаблон исключённых папок — папка пропускается
   целиком (игры в списке не будет).
5. `ScanFolder` создаёт `DetectedGame` с очищенным названием.
6. `Walk` рекурсивно собирает `.exe`.
7. Считает `ExcludedFiles` — сколько exe отброшено шаблонами.
8. Оценивает каждого кандидата, сортирует по `Score` убыванию, затем по размеру.
9. Первый кандидат становится `SelectedCandidate`.
10. Формирует `Draft`: `Name`, `WorkingDir` (по `WorkingDirMode`), `Cmd`
    (если есть кандидат).
11. Статус `New` или `NoExe`.
12. Ищет локальную обложку для превью (ошибки игнорируются).

### 9.2 Обход `Walk`

```
Walk(gameRoot, directory, depth):
    если MaxDepth > 0 и depth > MaxDepth → выход
    перечислить *.exe в текущей папке (TopDirectoryOnly)
        при UnauthorizedAccess/IOException → выход из метода
    для каждого файла:
        если имя или имя без расширения подходит под шаблон → excluded++, пропуск
        получить размер; при ошибке → пропуск
        добавить ExeCandidate(FullPath, RelativePath, Size)
    перечислить подпапки
        при UnauthorizedAccess/IOException → выход из метода
    для каждой подпапки:
        если имя подходит под шаблон папок → пропуск
        если атрибут ReparsePoint → пропуск
        Walk(..., depth + 1)
```

Особенности:

- Глубина считается от корня игры: 0 — сама папка игры.
- `MaxDepth = 1` означает «корень игры + один уровень вложенности»
  (проверка `depth > MaxDepth`).
- Поиск только файлов с расширением `.exe` (в Windows регистр не важен).
- Шаблоны применяются и к полному имени файла (`setup.exe`), и к имени без
  расширения (`setup`) — это позволяет ловить паттерны вида `unins*` и
  `ndp*.exe` одновременно.
- Символические ссылки и junction во вложенных папках не обходятся.
  Сама папка игры может быть junction — она сканируется.
- Ошибка доступа к файлам внутри папки приводит к `return` из `Walk`:
  подпапки этой папки тоже не просматриваются (см. раздел 17).
- `File.GetAttributes` для подпапки не обёрнут в try/catch — необычные
  файловые объекты могут прервать сканирование всей игры/скана.

### 9.3 Шаблоны исключений

Сопоставление — `System.IO.Enumeration.FileSystemName.MatchesSimpleExpression`
с `ignoreCase: true`.

Поддерживаются:

- `*` — любая последовательность символов;
- `?` — один символ;
- без учёта регистра;
- без поддержки спецсинтаксиса регулярных выражений.

Некорректный шаблон не роняет программу: исключение перехватывается, шаблон
считается несовпавшим. Опечатка в шаблоне, таким образом, молча ничего не
исключает.

Шаблоны папок применяются на **любом уровне** вложенности, а также к папкам
первого уровня — если папка игры называется `Support`, она будет пропущена.

### 9.4 Оценка кандидатов

Нормализация имени: нижний регистр, только буквы и цифры. Например,
`Half-Life 2` → `halflife2`.

| Условие | Баллы |
|---|---|
| имя exe полностью совпадает с именем игры | **+100** |
| имя exe (≥3 символов) содержится в имени игры или наоборот | **+60** |
| имя exe (≥3 символов) начинается с имени игры или наоборот | **+40** |
| размер: `min(30, log10(размер) * 6)` | до **+30** |
| в относительном пути 0–1 обратный слэш (`a.exe`, `bin\a.exe`) | **+15** |
| в относительном пути 2 слэша (`bin\x64\a.exe`) | **+8** |
| путь содержит сегмент `bin`, `bin64`, `binaries`, `x64`, `win64`, `game`, `gamefiles` | **+12** |
| путь содержит `x86`, `win32`, `32-bit` | **−10** |
| имя содержит `launcher` | **−35** |
| имя содержит `config`, `editor`, `benchmark`, `tool`, `server` | **−30** |
| имя содержит `crash`, `report`, `helper` | **−45** |

Сортировка: по `Score` убыванию, при равенстве — по размеру убыванию.
Первый элемент выбирается автоматически.

Практические следствия:

- Крупный `game.exe` в корне почти всегда побеждает.
- `launcher.exe` может остаться первым, если других кандидатов нет.
- `UnityCrashHandler64.exe` и подобные обычно отсекаются ещё шаблонами.
- Для игр с `bin\win64\Game.exe` и `bin\win32\Game.exe` выиграет 64-битный.

### 9.5 Очистка названия

`CleanGameName`:

1. `_` заменяется на пробел.
2. Удаляется хвост версии/сборки по регулярному выражению:
   `v1.2`, `1.0.3`, `1.2.3 final`, `repack`, `build 123`, `update 5`,
   `hotfix`, `dlc1` и их комбинации.
3. Схлопываются повторные пробелы.
4. Обрезаются пробелы, `-`, `.`, `_` по краям.
5. Если ничего не осталось — возвращается исходное имя папки.

Примеры:

| Папка | Название |
|---|---|
| `Half-Life_2_v1.0.3` | `Half-Life 2` |
| `DOOM Eternal (1.2.3 repack)` | `DOOM Eternal` |
| `Game_v1.0.0.123_hotfix` | `Game` |
| `_` | `_` |

Название можно изменить вручную в редакторе; при добавлении пустое имя
заменяется на `Name` игры.

### 9.6 Прогресс и отмена

- Прогресс сообщается **по папкам игр**, а не по файлам: `Сканирование 3/48: Имя`.
- `CancellationToken` проверяется между папками, файлами и подпапками.
- Отмена предусмотрена в коде: новый скан отменяет предыдущий, закрытие окна
  отменяет текущий. Отдельной кнопки «Отмена» в интерфейсе нет.
- После отмены статус показывает «Сканирование отменено.», но кнопка
  «Сканировать» снова включается только в `finally`.

## 10. Сопоставление с существующим конфигом

`GameMatcher.Apply(games, config)` вызывается после сканирования, после
загрузки конфига, после сохранения, добавления, правки и удаления записей.

Правила поиска (в порядке приоритета):

1. **Exe внутри папки игры.** Если `cmd` записи указывает на файл, лежащий
   внутри `FolderPath` (проверка нормализованных путей), запись считается
   совпадением.
2. **Рабочая папка.** Если `working-dir` записи совпадает с папкой игры или
   лежит внутри неё (например, это папка `bin\x64` выбранного exe).
3. **Название.** Если нормализованные названия совпадают **и** у записи
   непустой `cmd`.

Дополнительно при совпадении:

- `ExistingApp` указывает на запись;
- `Status = Existing`;
- `IsSelected = false`;
- если exe из `cmd` совпал с одним из найденных кандидатов, он становится
  `SelectedCandidate`;
- превью берётся из `image-path`, если файл существует.

Следствия:

- Игра не будет добавлена повторно, даже если папка переименована, но
  `working-dir` остался прежним.
- Запись с пустым `cmd` не сопоставляется по имени (только по папке/working-dir).
- Если в конфиге есть дубликаты, находится первый; какие-либо предупреждения
  о дубликатах отсутствуют.
- Сопоставление не учитывает регистр и прямые/обратные слэши.
- Сопоставление по имени не проверяет, что игра действительно та же: две разные
  игры с одинаковым названием будут считаться одной.

## 11. Добавление и редактирование записей

### 11.1 Черновик (`Draft`)

При сканировании для каждой игры создаётся `AppEntry`:

```csharp
new AppEntry {
    Name = game.Name,
    // WorkingDirMode.ExeFolder — по умолчанию; также GameFolder или Empty.
    WorkingDir = WorkingDirUtil.Resolve(mode, game.FolderPath, selectedCandidate?.FullPath),
    Cmd = selectedCandidate is null ? "" : "\"путь\\к\\exe\""
}
```

`Uuid` не задаётся до добавления. Остальные поля берут значения по умолчанию
(`auto-detach: true`, `wait-all: true`, `allow-client-commands: true`,
`exit-timeout: 5`, `scale-factor: 100`).

### 11.2 Состояния строки

| Состояние | Фон | Галочка | ComboBox | Текст статуса |
|---|---|---|---|---|
| `New` | белый | доступна, если есть кандидаты | все кандидаты, можно менять | — |
| `Existing` | светло-зелёный | включена и заблокирована | только текущий exe, заблокирован | «уже в конфиге» |
| `NoExe` | серый | заблокирована | «exe не найдены (исключено файлов: N)» | «нет exe» |

Тултипы объясняют, почему галочка недоступна.

При смене exe в `New`-строке:

- `SelectedCandidate` обновляется;
- `Draft.Cmd` пересобирается с сохранением **уже введённых аргументов**;
- `Draft.WorkingDir` пересчитывается по настройке `WorkingDirMode`
  (папка игры / папка exe / пусто).

Превью: для `Existing` — `image-path` записи; иначе — локальная обложка,
найденная при сканировании, либо `Draft.ImagePath`.

### 11.3 «Добавить отмеченные»

`AddSelectedGames`:

1. Если конфига нет — создаётся новый в памяти.
2. Для каждой игры `New` + `IsSelected`:
   - клон `Draft`;
   - `Uuid = Guid.NewGuid()` при отсутствии;
   - `Name`, `WorkingDir`, `Cmd` заполняются при пустоте; `WorkingDir`
     вычисляется по `WorkingDirMode`;
   - если `ImagePath` пуст и есть выбранный exe — **извлекается иконка exe**
     (`<slug>-icon.png`), локальная найденная обложка при этом не используется;
   - запись добавляется в конец `Apps`.
3. Игра переводится в `Existing`, галочка снимается, превью обновляется.
4. `MarkDirty`, перестройка обеих вкладок, сообщение «Добавлено записей: N».

Важно: добавление не сохраняет файл автоматически. Нужно нажать «Сохранить»
или «Сохранить как…».

### 11.4 Редактирование

**Новая игра** (`EditGame`): открывается `AppEditForm` с копией черновика
(`isNew: true`). После OK:

- черновик заменяется результатом;
- имя игры обновляется;
- если `Cmd` пуст и есть кандидат — команда восстанавливается (намеренно
  очистить команду у новой игры через редактор нельзя);
- превью обновляется, если файл обложки существует.

**Существующая игра** (`Existing`): открывается редактор **записи конфига**
по индексу. После OK:

- при пустом `uuid` подставляется старый или новый;
- запись заменяется в списке;
- `MarkDirty`, повторное сопоставление, перестройка строк.

**Ручное добавление**: создаётся пустая запись с новым `uuid`, значениями
`auto-detach`, `wait-all`, `allow-client-commands = true`,
`exit-timeout = 5`, `scale-factor = 100`. После OK добавляется в конец.
Проверка на дубликат отсутствует.

**Удаление**: подтверждение, удаление по индексу, `MarkDirty`, перестройка.

**Перемещение**: обмен с соседним элементом, `MarkDirty`, перестройка вкладки
конфига.

### 11.5 Редактор `AppEditForm`

Окно 780×720 (логически), две вкладки.

#### Вкладка «Основные»

| Поле | Поведение |
|---|---|
| Название | обязательное, обрезается |
| Файл (exe) | текст + «Обзор…» (`*.exe`) |
| Аргументы | текст, сохраняется отдельно, при сборке `cmd` добавляется после exe |
| Рабочая папка | текст + «Обзор…»; если пусто — вычисляется по `WorkingDirMode` (папка игры / папка exe / пусто) |
| Обложка | превью, «Выбрать файл…», «Найти в интернете…» |
| `elevated` | чекбокс |
| `auto-detach` | чекбокс |
| `wait-all` | чекбокс |
| `virtual-display` | чекбокс |
| `use-app-identity` | чекбокс |
| `per-client-app-identity` | чекбокс |
| `allow-client-commands` | чекбокс |
| `terminate-on-pause` | чекбокс |
| `exclude-global-prep-cmd` | чекбокс |
| `exclude-global-state-cmd` | чекбокс |
| `scale-factor` | 1–400 |
| `exit-timeout` | 0–600 |
| `gamepad` | редактируемый ComboBox: пусто, `disabled`, `auto`, `generic`, `ds4`, `ds5`, `switch`, `x360`, `xone`, `xseries` |

Сборка `cmd`: `CommandLineUtil.Combine(exe, args)`.

- Если exe содержит `://` (URI-команда Epic/Steam и т.п.), кавычки не
  добавляются.
- Иначе exe всегда заключается в кавычки, аргументы добавляются как есть.
- Пустой exe → пустой `cmd`.

Проверка при OK:

1. Название не пустое.
2. Если exe не URI и файл не существует — вопрос «Всё равно сохранить?».
3. Если выбрана новая обложка — она конвертируется в PNG и копируется в
   `covers` (имя по названию игры, перезапись разрешена).

#### Вкладка «JSON»

- Многострочное поле, Consolas 9.5, оба скроллбара, без переноса строк,
  `MaxLength = 2 000 000`.
- Показывает полный JSON записи, включая неизвестные поля.
- Изменения применяются:
  - при переходе с JSON на «Основные»;
  - при нажатии OK, если вкладка JSON активна и есть изменения;
  - при уходе с вкладки JSON (если изменения не применены — парсинг).
- При переходе **на** JSON содержимое всегда пересобирается из контролов.
- Ошибка парсинга показывает сообщение и блокирует переход/сохранение.
- Если в JSON нет `uuid`/`name`, подставляются текущие значения.
- После применения JSON контролы обновляются.

Практическое следствие: JSON — источник истины для полей, которых нет в
основном UI (`output`, `detached`, `prep-cmd`, `state-cmd`, произвольные поля).

### 11.6 Пакетные действия

Пакетные действия работают в двух местах: над списком «Найденные игры» и над
списком «Текущий конфиг». Набор кнопок одинаковый:

- **«Найти обложки…»** — для каждой отмеченной записи (если ничего не отмечено —
  для всех после подтверждения) последовательно перебирает провайдеров:
  GameDB → SteamGridDB → DuckDuckGo. Первый результат скачивается,
  конвертируется в PNG и сохраняется в `covers`; `ImagePath` и превью
  обновляются.
- **«Изменить отмеченные…»** — открывает `BatchEditForm`. Применяются только
  отмеченные поля: аргументы, рабочая папка, `scale-factor`, `exit-timeout`,
  `gamepad`, флаги Apollo (трёхпозиционные чекбоксы: серый — не менять,
  галочка — включить, пусто — выключить) и действие с обложками.

Рабочая папка в пакетном окне задаётся **не вводом пути**, а выбором правила
(как в настройках): папка игры, папка выбранного exe или пусто. Для каждой
записи путь вычисляется отдельно по её exe.

Обложки (`image-path`) в пакетном окне:

- «Не менять»;
- «Найти в интернете для каждой записи» — после применения полей запускается
  тот же пакетный поиск, что и по кнопке «Найти обложки…»;
- «Одна картинка для всех» — выбранный файл конвертируется в PNG и
  сохраняется в `covers` для каждой записи (имя — по названию игры);
- «Убрать обложку» — очищает `image-path`.

Различия вкладок:

- **«Найденные игры»** — цели выбираются обычной галочкой строки; если ничего
  не отмечено, предлагается обработать все игры со статусом `New`/`NoExe`.
  Правки применяются к черновикам `Draft` до нажатия «Добавить отмеченные».
- **«Текущий конфиг»** — у каждой строки появился отдельный чекбокс выбора;
  дополнительно есть **«Отметить все»** и **«Снять все»**. Если ничего не
  отмечено, предлагается обработать все записи конфига. Правки применяются
  сразу к записям `apps`, конфиг помечается изменённым (`*` в заголовке).

Особенности:

- выбор записей конфига (`AppEntry.IsSelected`) существует только в памяти и
  не записывается в `apps.json`;
- во время поиска обложек кнопки блокируются, в строке состояния идёт
  прогресс, кнопка **«Отмена»** прерывает обработку (уже обработанные записи
  остаются изменёнными);
- ошибка одного источника или одной записи не прерывает пакет: она учитывается
  в итоговой статистике;
- поиск выполняется последовательно, чтобы не упираться в лимиты API;
- как и при одиночном выборе, `<slug>.png` перезаписывается — две игры с
  одинаковым названием могут затереть обложку друг друга (см. 17).

### 11.7 Несохранённые изменения

- `_configDirty` ставится при любом изменении конфига.
- Заголовок окна получает `*`.
- При закрытии, смене конфига, создании нового — вопрос
  «Сохранить / Не сохранять / Отмена».
- Если сохранение при закрытии не удалось, окно не закрывается.

## 12. Обложки

### 12.1 Где хранятся

См. 8.3. В `apps.json` записывается **полный** путь к PNG.

Если папка обложек не задана и конфиг ещё не выбран, используется
`covers` рядом с `.exe`; после выбора конфига путь может измениться — это
следует учитывать при добавлении игр до выбора конфига.

### 12.2 Поиск локальной обложки

`CoverService.FindLocalCover(folder, name)`:

1. Сканирует файлы в корне папки игры.
2. Дополнительно — в подпапках:
   `artwork`, `cover`, `covers`, `box`, `art`, `media`, `images`, `screenshots`.
3. Только верхний уровень каждой из этих папок.
4. Расширения: `.png`, `.jpg`, `.jpeg`, `.bmp`, `.gif`.
5. Файл должен быть ≥ 512 байт.
6. Изображение должно открываться и быть ≥ 100×100.

Оценка:

| Условие | Баллы |
|---|---|
| нормализованное имя файла == названию игры | **+60** |
| имя содержит `cover`, `box`, `poster`, `artwork`, `folder` | **+50** |
| имя (≥4 символов) содержится в названии игры | **+35** |
| имя содержит `logo`, `icon`, `thumb` | **+5** |
| прочее | **+15** |
| портретная ориентация | **+25** |
| соотношение сторон 1.2–2.0 | **+10** |
| `log10(ширина × высота) × 2` | до нескольких баллов |
| любая сторона < 200 px | **−30** |
| файл лежит прямо в корне игры | **+4** |

Возвращается лучший по сумме. Ошибки чтения файлов игнорируются.

Найденная обложка используется **только для превью** в списке найденных игр.
При добавлении записи она не копируется в `covers` — вместо неё берётся
иконка exe (см. 17).

### 12.3 Иконка exe

`ExtractExeIcon`:

- `Icon.ExtractAssociatedIcon(exePath)`;
- рисуется на прозрачном `Bitmap` 128×128 с высококачественной интерполяцией;
- сохраняется как `<slug>-icon.png`;
- `overwrite: false` — при совпадении имени добавляется `-2`, `-3`, … до 999,
  затем GUID;
- любая ошибка → `null` (без исключения).

Иконка — «запасная» обложка, обычно хуже нормальной, но не требует сети.

### 12.4 GameDB (IGDB)

Открытый каталог **LizardByte GameDB** — тот же источник, который использует
Apollo в своём встроенном поиске обложек. Ключ не нужен, но нужен интернет.

GameDB — это выгрузка IGDB, разложенная на статические JSON-файлы:

| Что | URL |
|---|---|
| индекс по префиксу | `https://raw.githubusercontent.com/LizardByte/GameDB/gh-pages/buckets/<bucket>.json` |
| карточка игры | `https://raw.githubusercontent.com/LizardByte/GameDB/gh-pages/games/<id>.json` |
| запасной хост | `https://app.lizardbyte.dev/GameDB/...` (тот же путь) |
| превью обложки | `https://images.igdb.com/igdb/image/upload/t_cover_big/<slug>.jpg` |
| полная обложка | `https://images.igdb.com/igdb/image/upload/t_cover_big_2x/<slug>.png` |

Алгоритм повторяет Apollo (`apps.html`, `searchCovers`):

1. **Bucket.** Берутся первые два символа исходного названия, приводятся к
   нижнему регистру, остаются только `a-z0-9`. Если ничего не осталось —
   используется bucket `@` (туда GameDB складывает названия, начинающиеся
   не с латиницы).
2. Загружается `buckets/<bucket>.json` — объект вида
   `{ "<id>": { "name": "..." }, ... }`.
3. Названия нормализуются (нижний регистр, без диакритики и разделителей)
   и сравниваются с запросом. Ранжирование:
   - точное совпадение;
   - начинается с запроса;
   - содержит запрос.
4. Берутся до 12 лучших совпадений.
5. Для каждой игры загружается `games/<id>.json`, из поля
   `cover.url` извлекается IGDB-slug (`co1xbv` из
   `//images.igdb.com/.../t_thumb/co1xbv.jpg`).
6. В результат попадают два URL: `t_cover_big/*.jpg` для превью и
   `t_cover_big_2x/*.png` для сохранения — как в Apollo.

**Дополнительные fallback-и (сверх Apollo).** Если полное название не
нашлось, поиск повторяется по первым двум словам, затем по первому слову
(если оно длиннее 3 символов). Это помогает папкам вида
`Battlefield V (2018)` или `The Witcher 3 Wild Hunt`. Дополнительно
пробуются bucket по первым двум буквенно-цифровым символам и по первой
букве — для названий, начинающихся с пунктуации.

**Кэш.** В памяти процесса:

- bucket — 6 часов, максимум 8 bucket-файлов;
- отрицательный результат (нет файла/обложки) — 10 минут;
- найденный slug обложки — 24 часа, максимум 1000 записей.

Кэш не сбрасывается кнопкой «Очистить кэш превью» (она относится к файлам
в `cache\covers`), но исчезает при перезапуске программы.

**Размеры.** GameDB не отдаёт ширину/высоту обложки, поэтому
`CoverResult.Width/Height` равны `0`. Окно выбора подставляет реальные
размеры после загрузки превью.

**Ограничение.** GameDB индексирует названия на языке оригинала (в
основном английском). Локализованные bucket есть только для `eu`, `ja-jp`
и `ko-kr`; русского (`ru`) нет. Поэтому папка `Ведьмак 3` ничего не найдёт,
а `The Witcher 3` — найдёт. Для русских названий используйте SteamGridDB,
ручной выбор или переименуйте игру в редакторе перед поиском.

### 12.5 SteamGridDB

Официальный API `https://www.steamgriddb.com/api/v2`, Bearer-токен из настроек.

Алгоритм:

1. Если ключ пуст — исключение с просьбой открыть настройки.
2. `GET /search/autocomplete/{query}`.
3. Берутся первые 4 игры.
4. Для каждой:
   - `GET /grids/game/{id}?types=static&nsfw=false&humor=false&dimensions=600x900,342x482,660x930`;
   - если пусто — повтор без `dimensions`;
   - результаты добавляются, пока не наберётся 40.
5. В результат попадают `url`, `thumb`, `width`, `height`.

Ошибки HTTP показываются пользователю с кодом и подсказкой проверить ключ.
Таймаут HTTP-клиента — 20 секунд. User-Agent представляет браузер и программу.

### 12.6 DuckDuckGo

Неофициальный источник, без ключа. Может перестать работать в любой момент.

1. `GET https://duckduckgo.com/?q=...&iax=images&ia=images`.
2. Из HTML регуляркой извлекается `vqd`.
3. `GET https://duckduckgo.com/i.js?l=us-en&o=json&f=,,,&p=1&q=...&vqd=...`
   с `Referer: https://duckduckgo.com/`.
4. Из `results` берутся до 30 изображений с `http(s)` URL.
5. Для каждого: `image` (полный URL), `thumbnail`, `title`, размеры.

Ограничения: нет официального API, возможны 403/429, капча, изменение
разметки; regex для `vqd` хрупкий.

### 12.7 Конвертация, имена, коллизии

`SaveCover(source, coversDir, gameName, overwrite = true)`:

1. Проверяет исходный файл.
2. Создаёт папку.
3. Строит путь `<slug>.png`.
4. Если исходник уже совпадает с целью — возвращает путь без перекодирования.
5. Иначе `Image.FromFile` → `Save(..., Png)`.

Разрешение не меняется, метаданные теряются, анимация GIF сохраняется только
первым кадром (стандартное поведение `System.Drawing`).

**Коллизии.** При `overwrite = true` (используется в `AppEditForm`) две разные
игры с одинаковым slug перезапишут обложку друг друга. Иконки exe используют
`overwrite = false` и получают суффикс.

Slug:

- `a-z`, `0-9` — как есть;
- кириллица транслитерируется (`ж → zh`, `щ → sch`, `ю → yu`, `я → ya` и т.д.);
- всё остальное → `-`;
- повторные дефисы схлопываются, края обрезаются;
- максимум 60 символов;
- пустой результат → `cover`.

### 12.8 Окно выбора обложки

`CoverPickerForm`:

- ComboBox источника (`GameDB (IGDB)`, `SteamGridDB`, `DuckDuckGo`);
- поле названия (заполняется именем игры);
- «Найти» / Enter;
- сетка результатов: карточка 132×188, превью 148 px, подпись `Ш×В` (для
  GameDB размеры подставляются по факту загрузки превью);
- клик — выбор, двойной клик — выбор и закрытие;
- превью загружаются асинхронно, не более 4 одновременно;
- отмена поиска при новом запросе и при закрытии;
- подсказка об особенностях источника.

После выбора `AppEditForm` скачивает полное изображение в кэш и показывает
превью. В `apps.json` путь попадёт только после OK (файл конвертируется и
копируется в `covers`).

### 12.9 Кэш

Скачанные изображения лежат в `cache\covers`. Очистка — вручную из настроек.
Кэш не проверяется на актуальность и не ограничен по размеру.

### 12.10 Ключевое ограничение

Локальная обложка, найденная при сканировании, **не попадает в конфиг**
при «Добавить отмеченные» — используется только иконка exe. Чтобы использовать
локальную обложку, нужно открыть редактор игры и выбрать файл вручную либо
выбрать онлайн-обложку. Это главный функциональный недочёт текущей версии
(см. раздел 17, пункт 1).

## 14. DPI и масштабирование

### 14.1 Как сделано

- В проекте объявлен `ApplicationHighDpiMode = PerMonitorV2`.
- Все формы создаются кодом, поэтому `AutoScaleMode = AutoScaleMode.None`.
- После создания окна (`OnLoad`) вызывается:
  1. `DpiScale.Refresh(this)` — `Factor = DeviceDpi / 96`;
  2. `DpiScale.ScaleTree(this)` — рекурсивное масштабирование;
  3. установка логического размера окна через `SizeOf`;
  4. `DpiScale.FitToScreen(this)`.
- Строки списков и превью создаются во время работы и сразу используют
  `DpiScale.Px` / `DpiScale.Pad`.

`ScaleTree` масштабирует у всех дочерних контролов:

- `Size`;
- `Margin`;
- `Padding`;
- `MinimumSize` / `MaximumSize` (если заданы);
- абсолютные `ColumnStyle.Width` и `RowStyle.Height` таблиц.

Процентные и `AutoSize` размеры не трогаются — их пересчитывает layout.

### 14.2 Зачем так

Стандартный `AutoScaleMode.Dpi` + `PerformAutoScale()` в тестах оказался
непредсказуемым для программно созданных форм: масштаб зависел от момента
вызова (конструктор / `OnLoad` / `Shown`) и от порядка создания контролов.
Ручной вариант даёт одинаковый результат на 100 % и 200 %.

Проверено визуально на 3840×2160 при 200 %:

- главное окно — 2160×1520;
- `AppEditForm` — обе вкладки;
- `SettingsForm` — 1600×1640 (открывалось из реального меню);
- `CoverPickerForm` — 1840×1280;
- выравнивание подписей и полей исправлено, «Папка для обложек» расширена.

### 14.3 Ограничения подхода

- `DpiScale.Factor` — статическое глобальное состояние. При переносе окна на
  монитор с другим DPI автоматического пересчёта нет: `DpiChanged` не
  обрабатывается. Уже созданные контролы сохраняют старый масштаб.
- Если открыть форму на другом мониторе, `Refresh` изменит глобальный `Factor`,
  а новые строки будут масштабироваться уже по новому значению — возможна
  несогласованность внутри одного окна.
- `AutoScaleMode.None` означает, что ОС не масштабирует формы автоматически;
  вся ответственность на `DpiScale`.
- `MinimumSize` тоже масштабируется: на маленьком экране с высоким DPI окно
  может не поместиться, так как `FitToScreen` не может уменьшить его ниже
  минимума.
- Ширина строк вычисляется с фиксированным вычетом 24 px (предполагаемый
  скроллбар), что не учитывает системные метрики и DPI.

## 15. Сохранение и целостность данных

### 15.1 Конфиг

- Сериализация в память → запись `.tmp` → `.bak` + `File.Replace` → готово.
- Кодировка UTF-8 без BOM.
- Если Apollo удерживает файл, `File.Replace` может упасть; запасной вариант
  копирует/удаляет/перемещает. Если и это не удалось — пользователь увидит
  ошибку с советом закрыть Apollo или использовать «Сохранить как…».
- `.tmp` при ошибке не удаляется автоматически.
- `.bak` перезаписывается при каждом сохранении (хранится только предыдущая
  версия).

### 15.2 Настройки

- Пишутся при: изменении папки игр (по `Leave`), загрузке конфига,
  сохранении конфига, закрытии окна, сохранении настроек.
- Каждое сохранение создаёт/перезаписывает `settings.json.bak`.
- При ошибке записи показывается предупреждение, работа продолжается.

### 15.3 Защита от потери изменений

- Флаг `_configDirty` и звёздочка в заголовке.
- Подтверждение при закрытии, смене конфига, создании нового.
- При закрытии с несохранёнными изменениями можно выбрать «Отмена» и остаться.

### 15.4 Чего нет

- Нет отслеживания внешних изменений файла: если Apollo или другой редактор
  изменит `apps.json` после загрузки, сохранение из программы перезапишет
  изменения (кроме `.bak`).
- Нет блокировки файла и защиты от двух одновременно запущенных экземпляров.
- Нет журнала операций и отката, кроме `.bak`.

## 16. Обработка ошибок

| Место | Поведение |
|---|---|
| Чтение `settings.json` | ошибка → настройки по умолчанию + предупреждение после старта |
| Запись `settings.json` | `MessageBox` + продолжение работы |
| Чтение `apps.json` | `MessageBox` (или статус при тихом старте) |
| Запись `apps.json` | `MessageBox` с подсказкой про Apollo |
| Сканирование | `MessageBox`, статус «Ошибка сканирования.» |
| Обход папок | ошибки доступа/IO молча пропускаются |
| Размер файла | ошибка → файл пропускается |
| Локальная обложка | ошибки игнорируются |
| Иконка exe | любая ошибка → `null` |
| Онлайн-поиск | сообщение в окне выбора |
| Скачивание обложки | `MessageBox`, подсказка в редакторе |
| Некорректный JSON в редакторе | предупреждение, переход/OK блокируется |
| Глобальное исключение | `MessageBox` с полным стектрейсом |

## 17. Текущие недостатки

Ниже — честный список того, что уже видно в коде и поведении. Приоритеты:
**P0** — может привести к потере данных или делает функцию бесполезной;
**P1** — заметно мешает работе; **P2** — качество жизни; **P3** — мелочи.

### Функциональные

1. **P0. Локальная обложка не попадает в конфиг при добавлении.**
   `GameScanner` находит её только для превью (`CoverPreviewPath`), а
   `AddSelectedGames` всегда вызывает `ExtractExeIcon`. В результате
   пользователь видит красивую обложку в списке, добавляет игру — и получает
   иконку 128×128. Нужно при добавлении использовать найденную локальную
   обложку (`SaveCover`), а иконку — только как fallback.

2. **P0. Нет кнопки отмены сканирования.**
   `_scanCts` существует, отмена работает при закрытии/новом скане, статус
   умеет писать «Сканирование отменено», но пользователь не может нажать
   «Отмена». На большой библиотеке единственный выход — закрыть программу.

3. **P1. Относительный `image-path` не разрешается.**
   `GameRowControl.LoadPreview` и `GameMatcher` проверяют `File.Exists(path)`
   от текущего каталога процесса, а не от папки `apps.json`. Если в конфиге
   относительные пути, превью не появится.

4. **P1. Коллизии имён обложек.**
   `SaveCover` по умолчанию перезаписывает `<slug>.png`. Две игры с одинаковым
   названием (или одинаковым slug после транслитерации) затирают обложку друг
   друга. Стоит добавлять `uuid`/хэш или использовать `overwrite: false` с
   суффиксом.

5. **P1. Дубликаты записей не проверяются.**
   Ручное добавление и «Добавить отмеченные» не ищут уже существующую запись
   с тем же `cmd`/`working-dir`/именем. Сопоставление защищает только
   найденные игры, но не ручной ввод и не повторное нажатие кнопки после
   изменения статусов.

6. **P1. Нет очистки обложки.**
   В редакторе нельзя убрать `image-path`: можно только заменить файл или
   править JSON вручную. Кнопка «Убрать обложку» напрашивается.

7. **P1. Неверный exe нельзя исключить на уровне игры.**
   Можно выбрать другой exe, но нельзя пометить игру «не добавлять» кроме
   снятия галочки (что и так очевидно) или скрыть её из списка навсегда.

8. **P2. Нет выбора «все / ничего» для найденных игр.**
   На вкладке «Текущий конфиг» есть чекбоксы и «Отметить все / Снять все»,
   а в списке найденных игр отмечать приходится по одной — общей кнопки нет.
   Пакетное редактирование найденных игр меняет только черновики и не
   предлагает выборочных правил (например, «только игры без обложки»).

9. **P2. Нет поиска по exe-путям.**
   Фильтр ищет только по названию/папке/черновику.

10. **P2. Статус `NoExe` не предлагает действий.**
    Нельзя открыть папку, изменить шаблоны для этой игры или добавить запись
    вручную с указанием exe прямо из строки (кнопка «Изменить…» есть, но
    ComboBox заблокирован).

### Надёжность и целостность

11. **P1. Ошибка доступа к файлам обрывает обход подпапок.**
    В `Walk` при `UnauthorizedAccessException`/`IOException` на этапе
    перечисления файлов выполняется `return`, поэтому вложенные каталоги этой
    папки не обрабатываются. Лучше `continue` на уровне подпапок.

12. **P1. `File.GetAttributes` без обработки исключений.**
    Может выбросить исключение и прервать скан всей игры (или всего скана).

13. **P1. Нет обработки внешних изменений `apps.json`.**
    Сохранение затирает чужие правки; `.bak` спасает, но пользователь не
    предупреждён.

14. **P1. Нет защиты от двух экземпляров.**
    Два окна могут сохранять по очереди, `.bak` и `.tmp` будут конфликтовать.

15. **P2. `.tmp` не удаляется при ошибке.**
    После неудачного сохранения может остаться мусорный файл.

16. **P2. Запасной путь сохранения не транзакционен.**
    Между `File.Delete` и `File.Move` есть окно, в котором целевого файла нет.

17. **P2. `settings.json` в папке программы.**
    В `Program Files` запись запрещена; программа каждый раз предупреждает,
    но настройки не сохраняются. Нужен fallback в `%LOCALAPPDATA%` или
    явный portable-режим с проверкой прав.

18. **P2. API-ключ хранится в открытом виде.**
    `settings.json` рядом с exe легко скопировать/прочитать. Как минимум
    стоит предупредить; лучше — DPAPI.

19. **P2. Нет логирования.**
    Диагностика возможна только по сообщениям и вручную. Ошибки сканирования
    (пропущенные папки) нигде не фиксируются.

20. **P2. Глобальное исключение показывает стектрейс.**
    Пользователю — непонятно, разработчику — без лога. Нужен файл лога и
    человеческое сообщение. Кроме того, перехватывается только
    `Application.ThreadException`: исключения в фоновых задачах
    (`TaskScheduler.UnobservedTaskException`) и не-UI потоках
    (`AppDomain.UnhandledException`) не обрабатываются.

21. **P2. `MaxDepth` не ограничивается при загрузке.**
    В UI максимум 30, но `Normalize` не клампит значение. Конфиг с
    `MaxDepth: 1000` будет использован как есть.

### Производительность и UI

22. **P1. Полная перестройка строк.**
    Любое изменение фильтра/статуса/конфига удаляет и создаёт все контролы.
    Нет виртуализации; на тысячах игр возможны заметные подвисания.

23. **P1. Синхронная загрузка превью.**
    `LoadImageNoLock` читает и декодирует файл в UI-потоке при создании
    строки. Большие PNG/сетевые диски → фризы.

24. **P2. Строки не переиспользуются.**
    Каждое обновление заново создаёт `ToolTip`, `Font`, `PictureBox` и т.д.
    Ресурсы освобождаются, но нагрузка заметна.

25. **P2. Нет прогресс-бара.**
    Только текст в статусе; для длинного скана нет понимания, сколько осталось.

26. **P2. Нет сортировки списка.**
    Порядок — по имени папки (для игр) и по массиву (для конфига), без
    пользовательской сортировки/группировки.

27. **P3. Фиксированный вычет 24 px под скроллбар.**
    Может давать горизонтальную прокрутку или лишний отступ при другом DPI.

### DPI

28. **P1. Нет реакции на смену DPI/монитора.**
    `DpiChanged` не обрабатывается, `Factor` глобальный. Перенос окна на
    монитор с другим масштабом не пересчитывает интерфейс.

29. **P2. Риск двойного масштабирования.**
    `ScaleTree` не идемпотентен; если вызвать его повторно на той же форме
    (например, при будущей обработке `DpiChanged`), размеры удвоятся.

30. **P2. Минимальный размер может не поместиться на экран.**
    `MinimumSize` масштабируется и может превысить рабочую область.

31. **P3. `AutoScaleMode.None` означает отсутствие штатного поведения WinForms.**
    Любые новые контролы нужно не забыть масштабировать вручную.

### Обложки и сеть

32. **P1. Онлайн-источники неполные или неофициальные.**
    DuckDuckGo парсится через HTML и `vqd` регуляркой; может сломаться в любой
    момент, нет ретраев, ограничения частоты и капчи. GameDB покрывает только
    названия на языке оригинала: русского bucket нет, поэтому `Ведьмак 3`
    ничего не найдёт. Кроме того, GameDB не отдаёт размеры обложки, и они
    определяются только по загруженному превью.

33. **P2. Пакетный поиск берёт первый результат без выбора.**
    При пакетной обработке нельзя посмотреть варианты и выбрать другой
    источник/обложку для конкретной игры — это делается вручную через
    «Изменить… → Найти в интернете…».

34. **P2. Нет отмены скачивания обложки.**
    `DownloadToCacheAsync` вызывается с `CancellationToken.None`; закрытие
    редактора не прерывает загрузку.

35. **P2. Нет ограничения размера скачиваемого файла.**
    Большой URL может занять память/диск; проверяется только непустой ответ.

36. **P2. Кэш растёт без ограничений.**
    Нет автоочистки, счётчика размера, срока жизни.

37. **P3. Иконка exe всегда 128×128.**
    Мелкая для 4K; можно извлекать максимальный размер или несколько.

38. **P3. `CoverSource` не используется.**
    Источник обложки не сохраняется и не показывается в UI.

### Код и сопровождение

39. **P2. Нет тестов.**
    Ни одного unit/integration теста; парсер, сканер, slug и сопоставление
    проверялись вручную.

40. **P2. Нет `.gitignore`.**
    В папке проекта нет git-репозитория; при инициализации нужно исключить
    `bin`, `obj`, `*.user`, `settings.json`, `covers`, `cache`, `.vs`.

41. **P3. `ApolloGameScanner.csproj.user` содержит устаревшую ссылку на `Form1.cs`.**
    Файл не нужен в репозитории.

42. **P3. Строки интерфейса захардкожены.**
    Локализация только русская, без ресурсов.

43. **P3. Нет иконки приложения и манифеста.**
    Используется стандартная иконка; нет `requestedExecutionLevel` и
    DPI-манифеста (последнее компенсируется project-свойством).

44. **P3. Нет версии в заголовке/справке.**
    «О программе» показывает `1.0`, версия сборки не читается.

45. **P3. Нет отладочных символов/логгера в релизе.**
    Ошибки сложно диагностировать у пользователя.

## 20. Тестирование

### 20.1 Что проверять вручную

1. **Пустая папка игр** — сообщение, пустой список.

9. **Сопоставление по имени** — запись без exe внутри папки, но с тем же
   названием и непустым `cmd`.
10. **Неизвестные поля** — добавить `future-app-field` и `future-root`,
    сохранить, проверить наличие.
11. **`version: 1`** — после сохранения становится 2.
12. **`env`** — сохраняется без изменений.
13. **`.bak`** — после второго сохранения содержит предыдущую версию.
14. **Блокировка файла** — открыть `apps.json` с эксклюзивной блокировкой,

15. **Несохранённые изменения** — закрытие, смена конфига, новый конфиг.
16. **Ручное добавление** — пустые поля, проверка названия, несуществующий exe.
17. **JSON-вкладка** — добавить `prep-cmd`, вернуться, проверить; сломать JSON,

20. **Кэш** — очистка, повторный поиск.
21. **DPI** — 100 %, 150 %, 200 %, перенос между мониторами.
22. **Маленький экран** — 1366×768 при 150 %.
23. **Права** — запуск из `Program Files`, проверить предупреждение.
24. **Два экземпляра** — одновременное сохранение (ожидаемо: последний
    выигрывает; зафиксировать как известное ограничение).
25. **Рабочая папка** — три режима: папка игры, папка exe (по умолчанию),

  ключа; тогда `settings.json` нельзя переносить между машинами без потери
  ключа — задокументировать.
- Проверять URL обложек (только `http/https`, без `file:`).
- Ограничивать размер загрузки.

## 23. FAQ и типовые проблемы

### Программа не сохраняет настройки

Причина: папка с `.exe` недоступна для записи (например, `Program Files`).
Решение: перенести программу в папку пользователя (`D:\Tools\ApolloGameScanner`)
или выдать права на запись. В будущем — fallback в `%LOCALAPPDATA%`.

### «Не удалось сохранить конфиг… Apollo может удерживать файл»

Apollo может держать `apps.json` открытым. Закройте Apollo, сохраните, запустите
снова. Либо используйте «Сохранить как…» и затем замените файл вручную
(с резервной копией).

### Игра не появилась в списке

- Папка игры лежит не на первом уровне.
- Имя папки попало под шаблон исключённых папок.
- Папка пустая или содержит только не-exe файлы — игра будет со статусом
  `NoExe`, но всё равно появится.
- Ошибка доступа к папке — обход мог прерваться (см. 17.11).

### У игры нет exe

- Все exe исключены шаблонами — в строке будет «исключено файлов: N».
- Игра использует `.bat`, `.lnk`, launcher в другой папке.
- Exe лежит глубже `MaxDepth`.
- Это не игра, а папка с данными.

### Выбран не тот exe

- Смените его в ComboBox строки.
- Если нужного exe нет в списке — проверьте шаблоны исключений и глубину.
- Можно добавить игру вручную и указать любой exe.
- Помните: `launcher.exe` получает −35, но может остаться единственным.

### Игра считается существующей, хотя её нет в конфиге

Правила сопоставления: exe внутри папки, `working-dir`, нормализованное имя.
Возможно, другая запись имеет тот же `working-dir` или имя. Проверьте вкладку
«Текущий конфиг» и при необходимости удалите/переименуйте запись.

### Рабочая папка (`working-dir`) неверная

- По умолчанию `working-dir` — папка выбранного `.exe`, а не корень игры.
- Изменить правило: **Настройки → Рабочая папка (working-dir) новых записей**:
  папка игры, папка exe или пусто.
- Настройка применяется при сканировании, смене exe и добавлении новых
  записей. Уже сохранённые записи конфига она не меняет — их нужно править
  вручную или через JSON.
- После смены режима пересканируйте папку, чтобы пересчитать черновики.
- Если для игры нужен нестандартный путь, укажите его в редакторе в поле
  «Рабочая папка».

### Как найти обложки сразу для многих игр

1. Отметьте нужные игры галочками.
2. Нажмите **«Найти обложки…»** над списком.
3. Если ничего не отмечено, программа предложит обработать все новые игры.
4. Дождитесь окончания; прогресс и итог показываются в строке состояния.
   Кнопка **«Отмена»** прерывает обработку.

На вкладке **«Текущий конфиг»** работает та же кнопка: отметьте записи (или
нажмите **«Отметить все»**) и запустите поиск — обложки обновятся прямо в
конфиге, после чего его нужно сохранить.

Пакетный поиск берёт первый результат из GameDB → SteamGridDB → DuckDuckGo.
Чтобы выбрать другой вариант, откройте «Изменить… → Найти в интернете…».

### Как изменить несколько игр сразу

Отметьте игры и нажмите **«Изменить отмеченные…»**. В окне отметьте только те
поля, которые нужно применить (аргументы, рабочая папка, `scale-factor`,
`exit-timeout`, `gamepad`, флаги). Для флагов: серый — не менять, галочка —
включить, пусто — выключить.

Рабочая папка выбирается правилом: папка игры, папка выбранного exe или пусто —
путь вводить не нужно, он вычисляется для каждой записи.

Там же есть блок «Обложки»: не менять, найти в интернете для каждой записи,
поставить одну картинку для всех (файл конвертируется в PNG) или убрать
обложку. Это и есть массовое редактирование картинок; отдельная кнопка
«Найти обложки…» делает только поиск.

На вкладке **«Текущий конфиг»** кнопка работает так же, но изменения сразу
применяются к записям `apps` и помечают конфиг изменённым.

### Обложка не появилась

- Для существующей записи путь `image-path` может быть относительным или
  неверным.
- Локальная обложка при добавлении не копируется (см. 17.1) — выберите файл
  или онлайн-обложку вручную.
- Файл не PNG — Apollo принимает только PNG (программа конвертирует при
  сохранении).
- Файл занят другим процессом.

### GameDB не работает

- Нет доступа в интернет или блокируется `raw.githubusercontent.com` /
  `app.lizardbyte.dev` / `images.igdb.com`.
- Название на русском: GameDB индексирует в основном английские названия.
  Переименуйте игру в редакторе или используйте SteamGridDB/ручной выбор.
- Название начинается с цифры/пунктуации — провайдер пробует дополнительные
  bucket-варианты, но редкая игра может отсутствовать в GameDB.
- Сервер временно недоступен: повторите поиск через несколько минут (ошибки
  кэшируются на 10 минут).

### SteamGridDB не работает

- Не задан API-ключ.
- Ключ неверный/просрочен.
- Нет доступа в интернет или блокировка.
- Исчерпан лимит запросов.
Проверьте ключ на `https://www.steamgriddb.com/profile/preferences/api`.

### DuckDuckGo не работает

Это неофициальный источник. Возможны 403/429, капча, изменение HTML.
Используйте GameDB, SteamGridDB или ручной выбор файла.

### Интерфейс слишком крупный/мелкий

- Масштабирование ручное, по DPI монитора на момент открытия окна.
- При переносе на другой монитор перезапустите окно/программу.
- На маленьком экране с высоким DPI окно может не поместиться из-за
  масштабированного `MinimumSize`.

### Где лежат обложки и кэш?

- Обложки: `covers` рядом с `apps.json` (или путь из настроек).
- Кэш: `cache\covers` рядом с `.exe`.
- Настройки: `settings.json` рядом с `.exe`.

### Можно ли откатить сохранение?

Да, вручную: закройте программу, переименуйте `apps.json.bak` в `apps.json`.
Хранится только одна предыдущая версия.

## 24. Глоссарий

| Термин | Значение |
|---|---|
| **Apollo** | форк Sunshine для стриминга игр; использует `apps.json` |
| **Sunshine** | открытый сервер стриминга; формат конфига совместим |
| **`apps.json`** | корневой конфиг приложений Apollo: `version`, `env`, `apps` |
| **`settings.json`** | настройки сканера рядом с `.exe` |
| **Запись (entry)** | элемент массива `apps`, одна игра |
| **Черновик (Draft)** | временная запись, созданная при сканировании |
| **Кандидат (ExeCandidate)** | найденный `.exe` внутри папки игры |
| **Slug** | безопасное имя файла из названия игры |
| **GameDB** | открытая выгрузка IGDB от LizardByte; источник обложек Apollo |
| **Reparse point** | символическая ссылка/junction в NTFS |
| **DPI** | количество точек на дюйм; 96 = 100 %, 192 = 200 % |
| **PNG** | единственный формат обложек, который принимает Apollo |

## Итог

Приложение реализует полный базовый сценарий: **сканирование → проверка →
выбор exe → обложка → добавление → сохранение** — и делает это без потери
существующих данных Apollo. Обложки ищутся в GameDB (IGDB), SteamGridDB и
DuckDuckGo, а также локально и в иконке exe. Архитектура простая и
расширяемая, интерфейс русский, высокий DPI учтён.

Главные риски текущей версии: локальная обложка не попадает в конфиг при
добавлении, нет отмены сканирования, полная перестройка списков, отсутствие
тестов и логирования, а также необработанные внешние изменения `apps.json`.
Эти пункты вынесены в раздел 18 как обязательные к исправлению.
